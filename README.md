# ШХТ — шаховий хордовий тор для розподіленої обробки відео нейромережею YOLO26

Симулятор мережевого обміну в кластері вбудованих обчислювальних модулів. Код супроводжує курсову роботу
«Оптимізація топології обчислювального кластера вбудованих систем для задач розподіленої обробки даних»
(НТУУ «КПІ ім. Ігоря Сікорського», дисципліна «Дослідження і проектування комп’ютерних систем»).

## Про проєкт

Великі моделі комп’ютерного зору (наприклад, YOLO26x) не встигають обробляти відеопотік на одному вбудованому
модулі, тому кадр ділять між багатьма модулями, які постійно обмінюються проміжними даними. Кількість портів модуля
обмежена, тож час обміну визначається топологією з’єднань. У роботі запропоновано **шаховий хордовий тор
ШХТ(n; a, b)** — двовимірний тор зі степенем вузла 6, у якому напрямок двох хорд кожного вузла залежить від його
кольору в шаховому фарбуванні, а також три топологічно-орієнтовані алгоритми маршрутизації без таблиць.

Ключові результати для 256 вузлів (сітка 16×16, ШХТ(16; 2, 5)):

| Показник | ШХТ | 2D-тор | 3D-тор | Гіперкуб |
|---|---:|---:|---:|---:|
| Степінь вузла | 6 | 4 | 6 | 8 |
| Діаметр, переходів | 5 | 16 | 10 | 8 |
| Середня відстань, переходів | 3,671 | 8,031 | 5,020 | 4,016 |
| Умовна вартість N·D·S | 7 680 | 16 384 | 15 360 | 16 384 |

Мережевий обмін для відеопотоку Full HD (30 кадрів/с) займає 0,72–4,29 % кадрового бюджету залежно від моделі
YOLO26 (від n до x). Збір результатів усіма вузлами для YOLO26x виконується за 1,115 мс, що лише на 1,2 % більше
теоретичної межі.

## Що реалізовано

- **Топології:** ШХТ, 2D-решітка, 2D- і 3D-тор, гіперкуб; аналітичні характеристики класичних топологій.
- **ONE-TO-ONE:** формульна відстань за координатами й кольором вузлів та локальний вибір порту (без пошуку в графі).
  Відмовостійкий варіант ONE-TO-ONE-FT: швидка перша фаза плюс резервне (escape) дерево; доставка гарантована
  для всіх пар у межах однієї компоненти зв’язності при статичних відмовах.
- **ONE-TO-ALL:** локальне покривне дерево з ремонтом «осиротілих» вузлів при відмовах.
- **ALL-TO-ALL (all-gather):** N одночасних дерев розсилки з трьома способами вибору батька (за пріоритетом портів,
  за хешем, потокове балансування) і двома планувальниками каналів.
- **Безтупиковість:** віртуальні канали за номером переходу, перевірка ациклічності спільного графа залежностей
  каналів (алгоритм Кана).
- **Навантаження YOLO26:** розміри повідомлень із карти ознак P3 для моделей n, s, m, l, x, обмін гранями з сусідами
  без замикання країв зображення, оцінка частки кадрового бюджету та потрібної продуктивності вузла.
- **Відображення ШХТ на гіперкуб** за кодом Грея та рядкове, з розтягненням, перевантаженням і розширенням.

## Файли

| Файл | Призначення |
|---|---|
| `simulator_final.py` | Головний модуль: топології, алгоритми маршрутизації, дискретно-подійний симулятор, перевірка безтупиковості, моделі YOLO26 |
| `report_final.py` | Запускає експерименти й зберігає результати у вигляді таблиць (pandas): консоль, CSV, Markdown, Excel |
| `test_simulator_final.py` | 39 автотестів (unittest) |

Усі три файли мають лежати в одній папці. `report_final.py` і тести імпортують модуль `simulator_final`, тому
назву `simulator_final.py` змінювати не можна.

## Вимоги та встановлення

Python 3.10 або новіший. Сам симулятор використовує лише стандартну бібліотеку. Для звіту потрібні:

```bash
python -m pip install pandas openpyxl tabulate
```

`openpyxl` потрібен для Excel-файлу, `tabulate` — для таблиць у Markdown. Без них CSV та JSON усе одно зберігаються.

## Запуск

Тести:

```bash
python -m unittest test_simulator_final
```

Табличний звіт:

```bash
python report_final.py --quick              # швидкий прогін
python report_final.py                      # повний прогін (YOLO26x), кілька хвилин
python report_final.py e3 e8 e11            # лише вибрані експерименти
python report_final.py --model s --out res  # інша модель і папка результатів
python report_final.py --export-only        # повторний експорт із checkpoint.json
```

Експерименти звіту:

| Код | Зміст |
|---|---|
| `m0` | параметри моделей YOLO26 та розміри повідомлень |
| `e0` | топологічні характеристики при N < 1000, порівняння з класичними топологіями |
| `e1` | перевірка ONE-TO-ONE проти пошуку в ширину |
| `e2` | ONE-TO-ALL: дерева від усіх коренів |

| `e4` | граф залежностей каналів без відмов |
| `e5` | базове правило ONE-TO-ONE при статичних відмовах |
| `e6` | одночасна передача між довільними парами вузлів |
| `e7` | обмін гранями між сусідніми фрагментами кадру |
| `e8` | відмовостійкий ONE-TO-ONE-FT |
| `e9` | спільний граф залежностей маршрутів і розсилок |

Результати зберігаються в папку `--out` (за замовчуванням `report_out_final`): CSV для кожного експерименту,
`report.md`, `report.xlsx` (якщо встановлено `openpyxl`), `checks.csv` та `checkpoint.json`.

Окремі експерименти симулятора з консолі:

```bash
python simulator_final.py [--model n|s|m|l|x] [--quick] all
python simulator_final.py models | verify | broadcast | allgather | cdg | faults | traffic | halo | ft | deadlock | embed | yolo | directory
```

Приклад використання в коді:

```python
import simulator_final as S

T = S.ChessChordalTorus(16, 2, 5)                 # ШХТ(16; 2, 5), 256 вузлів
print(T.metrics())                                 # (діаметр, середня відстань)
print(S.route_one_to_one(T, 0, 137).path)          # маршрут без відмов
faults = S.sample_exact_faults(T, __import__("random").Random(1), 20, 50)
forest = S.build_escape_forest(T, faults)
print(S.route_one_to_one_ft(T, 0, 137, faults, forest, hc=7).path)
```

## Припущення та обмеження

- Моделюється **мережевий обмін**, а не виконання нейромережі: розміри повідомлень узято з карти ознак P3,
  а продуктивність вузла оцінено за кількістю операцій моделі та площею кадру.
- Канали повнодуплексні, 1 фліт за такт, 1 ГГц, вузли працюють у режимі all-port; черги необмежені,
  скінченні буфери й зворотний тиск не моделюються.
- Відмови **статичні** в межах однієї операції; escape-ліс і каталог міток вважаються узгодженими до її початку.
  Динамічні відмови під час передавання та протокол реконфігурації не реалізовано.
- Кількість обмінів гранями за кадр (`n_halo`) є параметром чутливості, а не величиною, виведеною з архітектури
  моделі.
- Параметри моделей YOLO26 (кількість каналів P3, GFLOPs) узято з виводу `model.info()` для завантажених ваг
  `yolo26n/s/m/l/x`; значення GFLOPs округлені.
- Результати отримано симуляцією; для висновків про реальні 30 кадрів/с потрібна перевірка на обладнанні.

## Відтворюваність

Усі випадкові експерименти використовують фіксовані початкові значення генератора, тому повторний запуск
дає однакові числа за однакової кількості випробувань. Режим `--quick` зменшує кількість випробувань, тож його
числа можуть відрізнятися від повного прогону.
